# DU30 · DUH 현장 작업 가이드 — 설치형 웹앱(PWA)

`DU30_DUH_Field_Guide_v3.html`(단일 파일, 9.9MB)을 **스마트폰·PC에 설치하고 오프라인으로 쓰는 앱**으로 바꾼 배포본입니다.

| 항목 | 원본 HTML | 앱(PWA) |
|---|---|---|
| 첫 화면 용량 | 9.9 MB 통째로 로딩 | 본문 88 KB, 이미지(103장)는 볼 때 로딩 |
| 설치 | 불가 | 홈 화면 아이콘, 주소창 없는 전체 화면 |
| 오프라인 | 파일을 받아둔 기기만 | 한 번 열면 전체(이미지 포함) 자동 저장 |
| 내용 갱신 | 파일 재배포 | 서버에서 교체 → 앱에 "새 버전 적용" 알림 |
| 작업 체크·입력값 | 기기 저장 | 동일 (기기별 저장, 서버 전송 없음) |

## 폴더 구성

```
du30-duh-field-guide-app/
├─ source/            ← 원본 HTML을 여기 둔다 (가장 최근 파일을 사용)
├─ pwa/               ← 서비스워커 원본, 설치 버튼·알림 스크립트/스타일
├─ scripts/
│   ├─ build.mjs      ← 빌드: 이미지 분리 + PWA 연결 → dist/
│   ├─ icons.mjs      ← 앱 아이콘(PNG/SVG) 생성
│   └─ serve.mjs      ← 로컬 확인용 서버
└─ dist/              ← ★ 배포할 결과물 (이 폴더만 올리면 됨)
```

Node.js 18 이상만 있으면 되고, 설치할 패키지는 없습니다.

## 빌드와 로컬 확인

```bash
npm run build
```

```bash
npm run serve
```

브라우저에서 `http://localhost:4173` 접속. (localhost는 HTTPS 없이도 PWA가 동작합니다.)

## 배포 (dist/ 폴더를 HTTPS 주소에 올리기)

> **주의**: 오프라인 저장과 앱 설치는 **HTTPS 주소에서만** 동작합니다. `http://사내IP`로 올리면 일반 웹페이지로만 열립니다.

**방법 1 — GitHub Pages (무료, 권장)**
1. GitHub에 새 저장소 생성 → `dist/` 안의 파일 전부(`.nojekyll` 포함)를 올림
2. Settings → Pages → Branch `main` / `/ (root)` 저장
3. `https://<계정>.github.io/<저장소>/` 주소를 팀원에게 공유
   - ⚠ 가이드 본문에 **장비 접속 계정·비밀번호(SFTP, moshell)** 가 들어 있습니다. 공개 저장소/공개 Pages에 올리면 누구나 볼 수 있으므로, 사내 서버(방법 3)나 접근 제한이 되는 곳을 우선 검토하거나 비밀번호를 지운 원본으로 빌드하세요.

**방법 2 — Netlify Drop (가입 후 드래그 한 번)**
`https://app.netlify.com/drop` 에 `dist` 폴더를 끌어다 놓으면 HTTPS 주소가 바로 생깁니다. 사이트 비밀번호 보호는 유료 요금제에서 가능합니다.

**방법 3 — 사내 웹서버 (HTTPS)**
`dist/` 내용을 웹 루트(또는 하위 경로)에 복사. 하위 경로에서도 그대로 동작합니다.
권장 헤더: `index.html`, `sw.js`는 `Cache-Control: no-cache` / `img/`, `icons/`는 장기 캐시.

## 팀원 설치 방법

- **안드로이드(Chrome/삼성 인터넷)**: 주소 접속 → 목차의 **[앱으로 설치]** 버튼, 또는 메뉴(⋮) → "앱 설치/홈 화면에 추가"
- **아이폰(Safari)**: 주소 접속 → 공유 버튼(□↑) → "홈 화면에 추가"
- **PC(Chrome/Edge)**: 주소창 오른쪽 설치 아이콘 클릭

처음 열 때 "오프라인 저장 완료" 알림이 뜨면, 그 뒤로는 장비 접속 중(외부망 끊김)에도 열립니다.

## 내용 갱신 절차

1. 새 HTML(v4 등)을 `source/`에 넣는다 (기존 파일은 지워도 되고, 가장 최근 파일이 자동 선택됨)
2. `npm run build`
3. 새 `dist/`로 서버 내용을 교체
4. 팀원 앱이 다음에 열릴 때 상단에 **"가이드 새 버전이 있습니다 · 지금 적용"** 표시

원본 HTML 구조(`<script id="assets">`, 사이드바 `side-foot`)가 바뀌어 빌드가 위치를 못 찾으면 빌드 단계에서 어떤 부분이 없는지 알려주고 멈춥니다.

## 동작 방식 (참고)

- 원본의 `asset(key)` 함수는 내장 base64 이미지를 돌려주는데, 빌드가 이 표를 `img/파일명.해시.webp` 경로로 바꿉니다. 본문 스크립트는 수정하지 않습니다.
- 서비스워커(`sw.js`)가 설치 시 모든 파일(114개, 약 7.5MB)을 저장하고, 이후 캐시 우선으로 응답합니다. 장비 웹(`https://169.254.2.2` 등) 같은 외부 주소 요청은 건드리지 않습니다.
- 버전은 전체 파일 내용의 해시라서, 내용이 바뀌면 자동으로 새 버전이 됩니다.
